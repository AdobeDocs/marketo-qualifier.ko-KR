# 설명서에 대한 기여

커뮤니티 구성원과 Adobe 직원의 기여를 환영합니다.

## Adobe 오픈 소스 행동 수칙

이 프로젝트는 [Adobe Open Source 행동 수칙](code-of-conduct.md) 또는
[.NET Foundation 행동 수칙](https://dotnetfoundation.org/code-of-conduct).
자세한 내용은 [기여](contributing.md)를 참조하십시오.

## Adobe 콘텐츠에 참여하는 방법

Adobe 직원이 아닌 경우 커뮤니티 기여도를 제출할 수 있습니다. 설명서 팀은 공개 저장소의 기여도를 검토하고 승인된 변경 내용을 Adobe의 내부 시스템과 동기화합니다.

Adobe 직원의 경우 개인 [Adobe GitHub 저장소](https://git.corp.adobe.com/AdobeDocs/)에 직접 참여하십시오. 자세한 내용은 Adobe 직원을 위한 Adobe Experience League 작성 안내서를 참조하십시오.

## 외부 참여자

### 부분 변경 사항

사소한 업데이트에 참여하는 경우:

1. 편집할 항목으로 이동합니다.
1. **에서 이 콘텐트가 유용했습니까?** 페이지 하단의 배너에서 **자세한 피드백 옵션**&#x200B;을 선택합니다.
1. **편집 제안**&#x200B;을 선택하고 변경 사항과 함께 가져오기 요청(PR)을 제출합니다.

   자세한 내용은 [Adobe 문서 콘텐츠 작가 가이드](https://experienceleague.adobe.com/ko/docs/contributor/contributor-guide/introduction)를 참조하십시오.

이 저장소의 설명서 및 코드 샘플에 대해 사용자가 제출하는 부분 수정 또는 설명은 Adobe 사용 약관의 적용을 받습니다.

### 주요 변경 사항 및 새로운 주제

주제를 만들거나 주요 변경 사항을 제안하려면 해당 Git 저장소의 **문제** 탭에서 문제를 제출하십시오. 설명서 팀원이 귀하와 협력하여 플랜에 동의하고 수정 사항을 게시합니다.

>[!NOTE]
>
>중요한 문서 또는 코드 변경 사항을 제출하는 경우 끌어오기 요청은 온라인 기여자 라이선스 계약(CLA)을 완료하라는 메시지를 표시합니다. 설명서 팀이 가져오기 요청을 검토하기 전에 CLA를 완료합니다.

### 도구

기본 편집 내용은 GitHub 인터페이스를 사용하십시오. 주요 기여의 경우 리포지토리를 포크합니다.

자세한 내용은 [Adobe 문서 콘텐츠 작가 가이드](https://experienceleague.adobe.com/ko/docs/contributor/contributor-guide/introduction)를 참조하십시오.

## 내부 참여자

기술 문서를 작성하는 Adobe 기술 문서 작성자, 프로그램 관리자 또는 제품 개발자인 경우 [개인 저장소](https://git.corp.adobe.com/AdobeDocs)를 사용하십시오.

* [인쇄 가능한 Markdown 치트 시트](https://guides.github.com/pdfs/markdown-cheatsheet-online.pdf)

## 레이블

공개 저장소는 끌어오기 요청에 레이블을 자동으로 할당합니다.

* **작성자에게 보낸 변경 내용**: 보류 중인 끌어오기 요청에 대한 알림을 작성자가 받았습니다.
* **병합 준비**: 끌어오기 요청을 검토할 준비가 되었습니다.
